# Own watcher lifetime at public write seams

A live watcher is exclusive across both its application root and resolved SQLite database, so every public writer must enforce the same lease rather than relying on a particular CLI, tray, or Web UI caller. `watch_vrc_logs()` therefore acquires the OS-backed app/database lease itself, while `LiveAppSessionRuntime` may acquire it synchronously for immediate conflict feedback and hand that verified lease into the watcher Module. Ownership begins before startup maintenance or capture creation and ends only after settlement, database commits, artifact cleanup, and finalization; the persistent lock files are locators, not runtime state. Web UI startup maintenance uses the same lease: active ownership is an expected skip, while configuration, SQLite, schema, repair, and commit failures remain visible as startup warnings.
